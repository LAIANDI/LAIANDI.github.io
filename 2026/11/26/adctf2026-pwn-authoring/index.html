ADCTF 2026 pwn 出题复盘：从 ret2win 到 FSOP

发表于2026-11-26|更新于2026-11-26|ctf
|浏览量:

这是我第一次给工作室的比赛完整出 pwn 方向。六道题，从最简单的 ret2win 到 glibc 2.35 的 FSOP。出题的目标不是把所有人拦在门外，而是让刚入门的人能拿到第一滴血，让打过几场比赛的人在第 5、6 题上真的花时间。

先把题目摆出来：

题目 难度 核心考点 一句话
badge Easy ret2win 访客登记，名字太长
plugin Easy RWX + shellcode 插件加载器，输入要编码
banner Normal 格式化字符串 + GOT 横幅生成器，标题里能写 %s
bastion Normal 栈迁移 白名单跳板机，只溢出到返回地址
draft Hard libc 泄漏 + ORW 记事本，崩溃后转储现场
ghost Expert UAF + tcache + FSOP 便签本，删除后副本还在

设计原则

定题之前先定了几条规则，后面每道题都按这个来：

  1. 一题一个核心考点。 不在同一道题里堆三个漏洞，选手卡住时能明确知道自己缺哪块。
  2. 每题留一个「钩子」。 一个反直觉的小设计，让背过模板的人停下来想一下：plugin 的 XOR、banner 的第二次 printf、bastion 的 -z now、draft 的 88 偏移、ghost 的浅拷贝。
  3. 防非预期解，但不堵死预期解。 该给 system 的地方给，该禁 execve 的地方禁；不靠「藏 flag」这种场外手段。
  4. 难度要能分层。 前两题送分，中间两题做区分，后两题拉开差距。理想情况是：新手 1–2 题，普通选手 3–4 题，强一点的 5 题，ghost 留给愿意啃的人。

1. badge：先让人拿到 flag

题面是 2019 年实习生写的访客登记系统，名字输入框没做长度限制。源码就三行关键逻辑：

没开 PIE、没开 canary，strings 里直接有 cat /flag，反查到一个 system("cat /flag") 的后门函数。偏移 0x20 + 8 = 40，跳过去就完事。

设计上的一个小细节：后门函数加了 force_align_arg_pointer。直接跳到函数入口时，rsp % 16 == 0，system 里的 movaps 会崩；加上这个属性，编译器会在函数开头对齐栈。下一题自己写 ROP 会再撞上对齐问题，正好在这里先埋个伏笔。

这是整场比赛的「第一滴血」题，预期 5–10 分钟。它不负责区分度，只负责让人愿意继续往下做。

2. plugin：NX 不是绝对的

题面是一个「插件加载器」，README 写着 Absolutely safe. Trust me.。核心逻辑：

它本来就打算执行你发的字节，所以这不是传统溢出，而是「怎么在 32 字节里塞下一段能用的 shellcode」。

两个限制：

  • 输入要编码：程序会逐字节 XOR 0x42，直接发原始 shellcode 执行的是乱码。
  • 最多 32 字节：shellcraft.sh() 在 amd64 上是 48 字节，会被截断。

预期解是手写 23 字节的 execve("/bin/sh", NULL, NULL)：

发之前 xor(shellcode, 0x42)。sendline 补的 \n 解码后落在 syscall 后面，execve 成功之后根本不会执行到，不会影响利用。

这题想传达的是：NX 保护的是栈和堆，mmap(PROT_EXEC) 申请的内存不受影响。别看到 NX 就条件反射只会 ROP。

3. banner：第二次 printf

题面是横幅生成器，标题和署名都会原样渲染。漏洞很直白：

两次都把用户输入当格式串。保护是 Partial RELRO + No PIE，GOT 可写、地址固定，基本就是冲着 GOT 去的。

钩子：程序里有一个从来没被调用过的函数，只执行 system("true")。它唯一的作用是让二进制链上 system@plt——否则只能泄漏 libc 再算 system，对 Normal 难度来说太重了。

预期解：

  1. 先用 %p 找到输入缓冲区对应的参数偏移，实测 %38$p 就是我们填的 8 个 A。
  2. 第一次输入用 fmtstr_payload(38, {printf@got: system@plt}) 把 printf@got 改成 system@plt。
  3. 第二次输入 /bin/sh，这次 printf(sign) 实际调用的是 system(sign)。

为什么第一次写 GOT、第二次才生效？因为 GOT 的解析发生在调用入口：第一次 printf 已经进 libc 了，写到一半不会改变当前这次调用；等它返回后，第二次 printf 才会读到新的 GOT 值。这个时序是这题最值得讲的地方。

4. bastion：只有一次 ret 的机会

题面是一台 2015 年的跳板机，只允许 whoami 和 ls。漏洞在 copy_to_stack：

0x20 的缓冲区拷 0x30，刚好覆盖 buf、saved rbp、saved ret，多一个字节都没有。栈上放不下 ROP 链，但 cmd 这个全局数组有 0x100 字节，而且 cmd_log 在它前面留了 4KB。

所以预期解是栈迁移：

第一次 leave 把 rsp 指到 saved ret，ret 跳到 leave; ret；第二次 leave 把 rsp 搬到 cmd+0x28，之后的链就在 .bss 里执行：

两个容易被忽略的工程细节：

  • -Wl,-z,now：迁移后 rsp 在 .bss，如果 system@plt 还没绑定，懒绑定会在 rsp 下面分配 xsave 区（本机约 0x9e0 字节），.bss 空间不够就直接 SIGSEGV。加 -z now 让所有 PLT 在启动时绑好。
  • cmd 前面的 4KB cmd_log：system 自己的栈帧要往下长，这块日志缓冲正好提供了空间。

这两个点不是为了「防选手」，而是本地测试时真的踩过；如果只按常规 ROP 写，远程会莫名其妙地崩。

题面是一个记事本，贴太长会「转储现场」。漏洞：

没 canary，但程序装了 seccomp，只杀 execve，没有 system，所以只能走 ORW。

第一个坑是偏移。 看源码会觉得是 0x40 + 8 = 72，但反汇编里 buf 在 rbp-0x50：

编译器为了放 ssize_t n，把 buf 挪到了 rbp-0x50，所以真实偏移是 0x50 + 8 = 88。这种「源码和汇编对不上」的题，比单纯堆 gadget 更接近真实漏洞分析。

第二个坑是泄漏。 用 write(1, puts@got, 8) 而不是 puts(puts@got)：puts 遇到 \x00 就停，libc 地址里随机一个零字节就会把泄漏截短。泄漏完还要回跳到 main，否则没有第二次输入机会。

第三个坑是路径。 open("/flag") 的字符串必须用 send(b"/flag\x00")，不能用 sendline——多出来的 \n 会让 open 直接失败。

6. ghost：删除之后

题面是一个便签本，删除功能「测试过很多次，不会残留」。实际上 del 里确实有 free 和 memset，问题出在「复制」：

struct note 里有一个裸指针 char *data。复制之后两个槽位指向同一块堆；删掉其中一个，另一个就拿着野指针，show 是 UAF 读，edit 是 UAF 写。再加上 show 用的是 write(1, data, size)，不会在 \0 停下，一次能把整个 chunk 读干净。

保护是 Full RELRO + PIE + NX，libc 2.35（__free_hook / __malloc_hook 已经没了），所以 GOT 和 hook 两条老路都断，只能打 FSOP。

预期链分四步：

  1. 泄 heap：tcache 的 fd 是 safe-linking 的 next ^ (chunk >> 12)。先 free 一个 chunk，show 出 chunk >> 12；再 free 一个相邻 chunk，两者同页，异或回去就能同时恢复两个地址。
  2. 泄 libc：tcache 每个 size 最多 7 个，先塞满 7 个 0x110，第 8 个进 unsorted bin，fd/bk = main_arena + 0x60。这份 libc 的偏移是 0x21ace0。
  3. 占堆：在泄 libc 之前先把 fake FILE、_wide_data、fake vtable 三块堆占好。顺序反了，malloc 会从 unsorted bin 里切一块走，地址全错。
  4. tcache poisoning → _IO_list_all：把 tcache[0x30] 链头的 fd 改成 _IO_list_all，两次 add 之后，第二次的 read 直接写在 _IO_list_all 上。退出时 exit → _IO_cleanup → _IO_flush_all_lockp → 假 FILE → _IO_wfile_overflow → _IO_wdoallocbuf → _wide_vtable->__doallocate，填成 system，_flags 写 " sh;"。

这题是整场唯一一道需要「堆布局」的题。它的难点不在单个 gadget，而在顺序：先占堆、再泄 libc、最后改链，顺序错一步地址就对不上。写题解时我特意把「为什么不能先泄 libc」单独讲了一段，因为这是我自己调试时卡最久的地方。

部署

六道题都用了同一套 Docker + socat 模板：

  • base ubuntu:22.04，只装 socat（draft/ghost 额外装 patchelf）
  • 每题一个非 root 用户 ctf，timeout 60，ulimit -c 0
  • 端口从 10001 到 10006，一题一个容器
  • flag 由平台通过 A1CTF_FLAG 注入，运行时写到 /flag，权限 400、属主 root

几个部署时踩过的坑：

  • 不要写 ${A1CTF_FLAG:-flag{xxx}}。默认值里的 } 会截断 shell 参数展开，导致 flag 变成 flag{xxx。正确做法是先取变量，再单独判断空值。
  • 固定 libc：draft 和 ghost 用 patchelf --set-interpreter + --set-rpath 绑定自带的 ld 和 libc.so.6，否则不同机器的 glibc 版本会让「本地能打通、远程打不通」。
  • 关掉 CET：编译加 -fcf-protection=none，避免 SHSTK/IBT 干扰传统 ROP 练习。
  • ghost 用 PIE + Full RELRO，是有意为之；如果还开 GOT 可写，这题就退化成普通的 tcache poisoning 了。

复盘

出题和做题是两种视角。做题时想的是「怎么打通」，出题时要想「他为什么会卡在这里」：

  • 难度曲线比单题难度更重要。 badge 和 plugin 负责让人留下来，banner 和 bastion 负责区分，draft 和 ghost 负责筛人。如果六道题都很难，大部分人第二题就走了。
  • 「钩子」要能被发现。 plugin 的 XOR 在题面里写了「已编码」，banner 的第二次 printf 在交互里能看到，draft 的偏移在反汇编里能对出来。好的钩子是「想到了就能过」，不是「猜不到就卡死」。
  • 本地能打通不等于远程能打通。 bastion 的 -z now、draft 的 libc、ghost 的堆地址，都是远程才暴露的问题。出题人必须自己用远程环境完整跑一遍。
  • 防非预期解要靠设计，不靠藏。 去掉 system、加 seccomp、开 Full RELRO，这些都是「让预期解成为唯一解」的正常手段；把 flag 藏起来、改题面、临时加限制，只会让选手觉得不公平。

如果下次还出 pwn，我想改进三点：给每道题写一个自动化的预期解脚本并纳入 CI；给 ghost 这种长链路题加一个「阶段性提示」机制；以及提前找没看过题的人做盲测，记录他们卡在第几分钟。

最后，感谢帮忙测试和提意见的队友。出题比想象中累，但看到有人在 draft 的 88 偏移上骂骂咧咧地打通，还是挺有意思的。
